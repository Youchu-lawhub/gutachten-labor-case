# 节点模式与大纲检查

节点模式是内部推理约定，不强制向用户输出JSON或执行日志。

```yaml
unit: U2
question: Q2a
objective: 特定赔偿请求
scope: substantive
main_form: R
fields: [D6, D4, D3]
node:
  id: U2.Q2a.1.2
  title: 本次解除是否不符合法定条件
  normative_function: prerequisite
  source: 经取得的规范及精确款项、版本、来源
  logic: AND
  children: [具体事由, 必要程序, 特别限制]
  embedded_form: E
  facts: 对应题目事实编号
  depth: core
  dependency: null
  missing: 仅列改变此节点判断的未知事实
```

`children`必须由本案具体规范重建，示例不意味着每次E都AND全部要素；不同通道先OR再分别AND。不能把示例字段直接打印为终稿内容。

大纲完成后核对：

- 目标是否有准确的权利人、相对方或行为人、效果与期间？
- 答案规范是否真能产生该效果？辅助或原则规范是否被错误当基础？
- 要件、例外、转介及效果是否完整，逻辑方向是否正确？
- 每个要件有规范与事实对应，证据指标没有伪装为法定AND条件？
- 嵌入子树是否必要，共享结论是否只分析一次？
- 责任范围与消灭扣减是否避免重复，R与程序外壳是否区分？
- 未被问的程序、权利、主体是否被自动扩张？
- 规范及案例来源是否实际取得，未核项是否限制相应结论？
- 报告是否保持每U大纲／正文对应，而不是评估报告十章？

将未满足项修正后交W2b。以上检查是内部核验，不新增用户确认闸门。
