# 义务面分析与请求权推导

劳动关系是继续性债之关系，双方互负多项给付义务与保护义务。请求权或源于原权（履行请求权），或源于义务违反后的救济权（损害赔偿、补偿、惩罚等）。分析任何案例，须先从法律关系出发扫描全部义务面，再从中推导请求权，而非从既有请求类型反向匹配。

## 1. 义务面分类

### 1.1 给付义务

给付义务是劳动关系的核心内容，决定双方应当提供什么：

**用人单位给付义务**：
- 报酬给付：工资、奖金、津贴、加班费、年终奖等
- 休假给付：法定节假日、年休假、婚丧假、产假等
- 保护给付：社会保险缴纳、劳动保护条件、职业危害防护
- 行为给付：出具离职证明、办理档案转移、继续履行合同等
- 补偿给付：经济补偿、赔偿金、医疗补助费等（法定或约定）

**劳动者给付义务**：
- 劳动给付：按约定提供劳动、完成工作任务
- 忠实义务：保密、竞业限制、利益冲突回避、勤勉尽责
- 附随义务：遵守合理指示、维护用人单位合法权益

### 1.2 保护义务

保护义务独立于给付义务，要求对方尽合理注意避免损害：

**用人单位保护义务**：
- 安全保障：提供安全卫生条件、防止工伤事故
- 人格保护：防止职场骚扰、歧视、侮辱
- 隐私保护：合理处理个人信息
- 健康保护：合理工时安排、防止过劳

**劳动者保护义务**：
- 安全操作：遵守安全规程、防止损害发生
- 财产保护：妥善保管用人单位财物
- 信息保护：不泄露商业秘密和个人信息

### 1.3 原权与救济权区分

**原权（履行请求权）**：义务正常履行时即存在的请求权。例如：
- 劳动者请求支付到期工资（报酬给付义务的原权）
- 用人单位请求劳动者提供劳动（劳动给付义务的原权）
- 劳动者请求安排年休假（休假给付义务的原权）

**救济权（义务违反后果）**：义务违反后产生的请求权。例如：
- 未签合同→二倍工资差额（法定制裁）
- 违法解除→赔偿金或继续履行＋期间工资（救济权）
- 未缴社保导致待遇损失→损害赔偿（救济权）
- 违反保护义务致损害→侵权赔偿（救济权）

同一义务违反可能同时产生多种救济：继续履行＋赔偿、补偿＋惩罚、返还＋损害。分别检视各自的成立要件，不因"都是赔偿"合并处理。

## 2. 义务面扫描流程

面对任何案例，按以下步骤扫描：

**步骤一：识别法律关系**

先确定案件涉及的劳动关系类型：
- 标准劳动关系（全日制）
- 非全日制用工
- 劳务派遣
- 平台用工（可能涉及不完全劳动关系或民事关系）
- 承包/外包关系
- 多重劳动关系

每种关系类型的义务面不同。平台用工可能不完全符合劳动关系，但仍须按政策文件检视平台应承担的劳动保障责任（最低工资、休息、安全卫生等）。

**步骤二：扫描全部义务面**

对每个法律关系主体，逐一检视：

1. **给付义务面**：
   - 报酬义务：本案涉及哪些报酬类型？是否已足额支付？
   - 休假义务：是否依法安排休假？未休是否支付补偿？
   - 社保义务：是否依法缴纳？是否导致待遇损失？
   - 行为义务：是否出具证明、办理手续、继续履行？

2. **保护义务面**：
   - 安全保障：是否发生工伤、职业病？
   - 人格保护：是否存在骚扰、歧视？
   - 健康保护：是否过劳、超时工作？

3. **劳动者义务面**（如案件涉及）：
   - 劳动给付：是否提供劳动？是否完成任务？
   - 忠实义务：是否违反保密、竞业？
   - 安全操作：是否违反规程致损？

**步骤三：从义务违反推导请求权**

对每个义务违反，推导可能的请求权：

- **原权请求**：义务到期未履行→请求履行（支付工资、安排休假、出具证明）
- **法定制裁**：法律明文规定违反后果→请求制裁（二倍工资、赔偿金）
- **损害赔偿**：义务违反致损害→请求赔偿（社保待遇损失、侵权损害）
- **补偿请求**：法定或约定补偿事由→请求补偿（经济补偿、医疗补助费）
- **返还请求**：无法律原因给付→请求返还（多付工资、押金）

每个请求权独立检视成立要件。同一事实可能触发多个请求权（竞合），分别检视后判断是否可同时主张或择一行使。

**步骤四：完整性校验**

扫描完成后，对照以下清单确认未遗漏：

- [ ] 报酬义务面：工资、加班费、奖金、津贴、年终奖
- [ ] 休假义务面：法定节假日、年休假、婚丧假、产假
- [ ] 社保义务面：五险缴纳、待遇损失
- [ ] 保护义务面：安全、人格、健康
- [ ] 行为义务面：证明出具、手续办理、继续履行
- [ ] 劳动者义务面：劳动给付、忠实义务、安全操作
- [ ] 法定制裁：二倍工资、赔偿金
- [ ] 补偿请求：经济补偿、医疗补助费
- [ ] 返还请求：多付工资、押金

未命中清单的项目不强行纳入；命中但未在设问范围内的事项，仅在必要时提示用户是否增加设问，不自动扩展分析范围。

## 3. 与既有分析框架的衔接

义务面扫描完成后，推导出的请求权进入既有分析流程：

- **元类型归属**：每个请求权归入 L/V/E/M/N/R/P/A 元类型，按对应标准程式展开
- **大纲生成**：按 outline-engine 从规范原文提取要件树
- **claim-type 文件**：作为校验参考，核对请求类型、计算参数、常见争议点，但不作为分析起点

claim-type 文件覆盖常见请求类型，但无法穷尽所有义务违反情形。义务面扫描保证即使遇到未编码的请求类型，也能从义务违反推导出请求权，再按既有框架分析。

## 4. 适用示例

**案例**：用人单位未安排年休假，劳动者请求支付未休年假工资。

**义务面分析**：
1. 识别法律关系：标准劳动关系
2. 扫描义务面：
   - 休假给付义务：用人单位应当安排年休假
   - 未安排年休假→义务违反
3. 推导请求权：
   - 原权：请求安排年休假（履行请求）
   - 法定后果：未安排→支付未休年假工资报酬（法定制裁）
4. 完整性校验：休假义务面已覆盖

**进入既有框架**：
- 元类型：R（给付请求）
- 规范基础：《职工带薪年休假条例》第5条
- 要件树：劳动关系存在→年休假资格→未安排事实→工资报酬计算
- claim-type 校验：remuneration-claims.md 中年假部分核对计算标准

义务面扫描确保不遗漏其他可能请求（如同时存在加班费未付、社保未缴等），即使案例未明确提及，扫描过程也会提示检视。
