# W4：核验与交付

一次系统检查，发现实质问题集中修改并定向复核。不循环。

## 1. 三维核验

### 维度一：增量法条校验

以 references/research-protocol.md §7 的 `verification-log.md` 为底稿逐条审计：

1. 正文引用与台账**双向对账**——正文出现的每个条号在台账中有记录，台账中每条在正文中至少出现一次；
2. 每条标记：
   - **〔通过〕**：台账有记录且现行有效，**或已失效但适用于本案行为时点**（依过渡条款与时际适用规则确认）
   - **〔需修订〕**：条号正确但原文差异、版本过期或内容不一致
   - **〔硬错〕**：条号不存在，**或已失效且不适用于本案任何行为时点** → 必须删除或替换
3. 三级降级下无法比对历史版本时如实标注降级，不记为通过；
4. 台账中当日已核验且能力槽级别未下降的记录，可跳过重新调用后端，仅做"台账—正文"一致性审计。

**工作目录版台账本身不外发**；审计完成后按 references/research-protocol.md §7.4 从中派生**三栏精简核验记录**，作为报告末尾标准节随正文一并交付。

### 维度二：大纲覆盖度 + 事实忠实

1. 每个确认的独立设问（U）有对应正文，嵌入前提不被误拆，主备救济与相对方关系完整；
2. 程式由目标效果决定——R 三层、其他专属程式和程序外壳没有互相错套；
3. 每个决定性要件有规范含义与事实归入，逻辑 AND／OR／例外没有漏项或颠倒；
4. 支付、抗辩、证明责任及无法确定的节点准确，既定事实未被制造为争议；
5. 金额基数、期间、倍率、上限、扣减和互斥关系可复算；行为给付的内容和期间可确定；金额计算须核验适用的规范层级（法律 / 行政法规 / 司法解释 / 部门规范性文件 / 地方标准），不同层级的计算规则不得混用；
6. 共同节点接口范围与正文一致，无一个 agent 认定 A 为单位另一个认定 B 为单位；
7. 每单元大纲与正文节点对应。
8. **事实覆盖率审计**（事实闭合原则）：逐一核对 W1 事实清单（F1, F2…），每个事实须满足下列之一：(a) 已映射到正文至少一个要件节点并被涵摄；(b) 属于背景信息不影响任何结论；(c) 已被当事人否认且无其他事实支撑；(d) 仅影响已排除的请求路径。未满足任何一项的事实须补充分析或说明原因。

## 2. 一次性修订

三维核验完成后，按以下优先级集中修订：

- **P1（硬错）**：条号不存在/已失效、大纲与正文不对应、程式错套 → 立即修正
- **P2（实质问题）**：要件漏项、金额计算错误、接口不一致 → 定向修正
- **P3（格式偏差）**：标题层级错误、校验标记缺失、段首空格遗漏 → 批量修正

修订后定向复核：仅验证修改项及其依赖项（条号变更→要件连锁、金额变更→合计与倍率、节点调整→交叉引用），最多一轮；未决问题就地标注并随报告交付。

## 3. 自动交付（无用户确认闸门）

W3 写作完成后自动进入 W4 核验与修订，不设置任何用户确认闸门。核验修订完成后直接输出最终 Markdown 报告文件，随后简短告知用户：

1. 文件路径与格式（Markdown）
2. 主要结论（逐问一行）
3. 影响结论可靠性的限制（降级标注、事实缺口等）
4. 可选 Word 转换：询问用户是否需要转为 Word 格式

不复述全案事实，不添加额外分析，不等待用户批准后再输出。

## 4. 交付

直接输出 Markdown 报告文件，交付文件**包含且仅包含**三部分（大纲 / 正文 / 核验记录）。其他内部工作表、检索日志、agent 协作笔记仍留在工作目录，不随报告附送。报告只按已确认 U 排列，大纲不预告实体结论，正文从假设展开；材料不足的结论留在对应要件和单元小结。引用规范或文献就地标明真实出处，不因要求来源而全文复制法条。

报告输出后，询问用户是否需要 Word 版本。需要时才依 format/output-format-spec.md 转换，排版与正文内容分别检查。
