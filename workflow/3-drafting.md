## 2. 劳动合同法对民法的参照适用规则

见 [methodology/labor-civil-law-interface.md](../methodology/labor-civil-law-interface.md)。写作过程中遇到劳动法对特定问题无明确规定的情形时，须按该文件区分事项类型（契约结构一般性漏洞 / 政策性权衡事项）并执行操作步骤，不得跳过判断直接以民法一般规定替代。

## 3. 准备与派工

主线程依据 `methodology/problem-units.md` 核对 U 编号及依赖。一个单元在主线程完成；至少两个单元且支持委派时，一单元一 agent，容量不足分批执行。没有委派能力时顺序完成，不因此减少分析内容。

禁止按内部请求节点 Q、请求族、相对人或单个要件自动派工。U 是确认的独立问题，Q 是其中具有特定目标效果的请求，派工包负责整个 U 而非任一 Q。一个 U 包含主备或并列 Q 时，分别保留各自规范、要件和小结。权限、规范及关系等前置问题没有独立设问时留在本单元内；前置问题属于独立 U 时，通过接口交接。共同事实、规范版本和术语只由主线程更新并同步。

### 可直接使用的 dispatch packet

```markdown
任务：完成 U[编号] 的完整鉴定式分析
独立设问：[确认后的原文或准确表述]
范围：[本单元须回答及不包含的事项]
方法标签：[W2 依 domain-router.md 核定的 L/E/R/V/M/N/P/A，可组合]
请求节点：[无／Q1、Q2……各自目标效果、相对人及主位／备位／并列关系]
共享事实：[facts-vN 的全文或可读路径；题目既定事实与真正缺口分开]
规范时点与地域：[案件时点、适用版本要求、相关地区]
统一术语：[术语表版本及称谓]
候选规范：[W2a 清单及已核对来源]
逐要件大纲：[W2b 依 methodology/outline-engine/OVERVIEW.md 生成的完整编号、各 Q 要件、规范对应]
举证责任分配：[各争议要件的举证方：劳动者 / 用人单位 / 倒置（注明规范依据）]
依赖：[无／依赖 Ux 的哪些结论；附已收到的 contract]
输出格式：[本单元（ 一 ）大纲及（ 二 ）正文的准确标题层级]
写作要求：自然鉴定式；待证判断→规范或定义→事实涵摄→小结；明显要件从简。
禁止：补造事实、猜前置结论、扩展新设问、默认事实摘要或风险清单。
交付：本单元成稿；独立接口 contract；法源登记（本单元新核验或新发现的条号、来源级别、标注状态及复用计数，供主线程写入台账）；内部说明仅列实质缺口、法源冲突与需协调事项。
```

派工内容中的范围说明、内部缺口记录与执行信息不自动复制进终稿。

## 4. 定向检索

依据已确认的逐要件大纲检索。先核对决定性规范文本、时间效力与地域，再按实际需要取得解释、裁判或学理。遵守研究协议的预算与停止条件，不因为标为核心争点就穷尽所有解释方法或强制检索大量类案。

金额计算涉及地方参数（最低工资、社平封顶线、失业金、病假下限、一裁终局金额线）的，先查案件工作目录地方参数缓存已沉淀值（核验日期超 90 天或受诉地无沉淀的，按 `references/local-data-sources.md` 对应类别行锁定入口运行时检索，取值经核验后写入案件工作目录缓存，按地域、版本、时间和来源索引）。

已有来源可共享但须核对适用性。新发现的决定性规范或冲突应向主线程说明并调整相关要件，不机械重走全部确认。只有确需增加独立设问、改变分析目标或实质扩张范围时，才返回范围确认。

写前查：正文写任一条号前先查 references/research-protocol.md §7 的 `verification-log.md`——已登且通过则复用，未登则按§6核验后在 contract 中登记新条号及其核验结果。同一会话当日已核验且级别未下降的条号直接复用，不重复调用后端。**多 agent 并行时，agent 只读台账、不直接写入**；新发现的条号、核验结果及复用计数由 agent 在 contract 的"法源登记"段提交，主线程合并单元时统一写入台账并对齐同条条文的解释与版本。

## 5. 大纲与正文逐项映射

每个单元依据其核定程式形成“（一）大纲／（二）正文”。大纲列真正审查的要件及规范，正文使用同一编号顺序完成论证；不能用检索卡、篇幅计划、深度标签或模块名称代替大纲。

核心问题自然写出待证判断，随后说明规范与必要定义，将题目事实归入要件并给出小结。无需机械使用”总起句／定义／涵摄／结论”四个标题。明显要件一句即可；请求权三层中的无争议部分简短说明，不制造空白章节。

举证责任随要件分配：每个争议要件在涵摄时标明举证责任归属。一般规则”谁主张谁举证”（《民事诉讼法》第 67 条第 1 款）；劳动争议中用人单位掌握管理的证据由用人单位提供（《调解仲裁法》第 6 条）；解除、终止、减发工资、工作年限计算等决定由用人单位负举证责任（司法解释一第 44 条）。不得一律倒置，也不得遗漏分配。

共同要件已在前置单元完成时，引用其具体结论与位置，说明该结论如何满足本单元要件。解除合法性不能直接推出所有救济结论。继续履行与期间工资等不同目标效果即使处于同一 U，也须按不同 Q 保留各自要件；主备救济不能归并为一套含糊的“后果选择”。金额计算须落入相应 Q 的责任范围，说明基数、期间、倍率及必要扣减，不重复两套计算章节。

R 域不限于金钱：请求交付文本、出具证明、提供保护、停止侵害或容忍特定行为，均须说明具体义务及可请求效果。M 权限审查、N 规范适用审查不能只写合同条款有效否；按核定大纲审查权限来源、作用范围及规范具体后果。“能否胜诉”的 P 审查作为相应单元外壳处理，不能擅自新增程序 U。

题目给定事实按既定前提使用。材料没有解除事由、日期或工资时，只在相应要件说明无法得出何种结论；不能凭仲裁金额、当事人称谓或他案裁判补齐。真正争议事实的证明责任紧随待证要件，不另堆默认举证章节。

### 5.5 法律解释方法贯穿

**根本立场**：法律解释方法（文义/体系/历史/目的）是论证的增强器，贯穿写作全程使用——不是"找不到权威依据时才启用的兜底"。即便已经从法规、案例、学术资源获得了观点素材，仍要用方法对这些素材进行检验、整合与显性化。

**触发条件**：要件含义为不确定法律概念/一般条款，或本案事实涵摄存在歧义、双方有合理争议、司法实践有分歧、引用素材彼此冲突。

**素材分级**（为方法提供论据，而非替代方法）：

1. **用户已注册的学术/实务文献类 KB**（脚注 [KB:]）——最权威
2. **法律数据库案例检索 + 全网学术/实务搜索**（脚注 [案例]/[联网]）——通常都要执行
3. **方法论自助式解释**（依 gutachten-writing-rules.md 独立完成）——不加脚注，正文展开方法步骤

无论调用到哪一级素材，解释段落都须显性展示方法在工作（文义边界 → 体系协调 → 历史/目的支撑，按需展开）。严禁 [模型推理]/[此观点尚需查证] 占位脚注（真实来源原则）。

## 6. 单元交付及依赖

各 agent 提交完整单元正文及 `problem-units.md` 规定的 contract。需要前置结论的 agent 在接收接口前，不给依赖该前提的确定结论。条件性接口按相同条件传递；存在矛盾时，由负责单元复核其规范与涵摄，主线程不能替 agent 猜事实或径直改出更确定的结论。

## 7. 主线程整合

主线程负责：

1. 按设问及依赖顺序合并单元，保留每单元大纲与正文映射。
2. 核对称谓、事实版本、规范时点、相同条文解释与金额参数。
3. 删除重复共同要件，改为准确交叉引用；保留不同 Q 的目标效果、特有要件及主备或并列关系，不能因共享前提删除独立责任根据。
4. 核对各接口与正文的结论边界；冲突交回原负责者修订。
5. 末尾按设问作简短结论，必要金额在对应请求或结论中列示。

默认不增加事实摘要、流程说明、检索日志、排除请求表、大范围风险清单、行动建议或重复结论摘要。用户明确需要诉讼评估附加内容时，另列附加交付，不侵入鉴定式正文。内部核验记录保留供 W4 使用。

## 8. 进入 W4 的条件

每个确认的独立设问已有完整分析；大纲中的决定性要件都有正文对应；前置接口已衔接；法源、金额及事实缺口均可定位。随后依 W4 核验交付，不额外设置写作确认闸门。
