# W0：首次启动强制访谈（入口硬性闸门）

本文件是 skill 的**入口闸门**，先于 W1。每次会话启动，先按 §1 判定是否首次启动；首次启动必须先完成本访谈并取得用户实际回答，才能进入 W1。

## 1. 触发判定（先于一切分析）

会话启动时检查工作根目录是否存在长期配置 `.user-config.md`（跨会话复用，区别于案件工作目录的运行时产物）：

- **不存在 → 首次启动**：本访谈为**硬性必经步骤**。必须通过交互式提问向用户提出 §2 必答项并**等待用户回答**；用户未回答前，**禁止进入 W1、禁止选定法源、禁止起草**。不得以“上下文已足够”“默认即可”“无配置也能分析”为由跳过访谈，或替用户假定答案后直接开工。
- **存在 → 已初始化（resume）**：读取 `.user-config.md` 载入 jurisdiction/mode/citation/format/confirmation/depth 与能力槽契约，**不再重复访谈**；仅当用户本次明确变更偏好、或案情受诉地与登记不一致时，就地确认差异项。

**交互方式**：优先使用运行环境的交互式提问工具（如 AskUserQuestion 类）逐项列出必答项并等待用户选择/回答；环境无交互工具时，以对话消息一次性列出必答项并等待用户回复。两种方式都必须取得用户实际回答，**不得自问自答、不得把推断值当作已回答**。

## 2. 必答项（首次启动必须问、必须由用户回答）

下列四项直接改变分析范围、口径、结论或法条核验级别，**首次启动必须问、必须由用户回答**。可从案情或对话推断的，将推断值作为**预选默认**呈现，请用户确认或修改——确认也是一种回答，但不得静默采用推断值：

1. **适用地域（jurisdiction）**——常用执业地／受诉地是哪个省市？直接决定地方参数与裁审口径（详见 §3）。
2. **使用场景（mode）**——案例研习／教学（academic）、律师办案（litigation）、合规审查（compliance）？决定是否展开全套程序、裁判主文与风险建议。
3. **输出与确认偏好**——引注方式（正文精确引注／脚注引注）、交付格式（Markdown／Word）、确认模式（分段确认／全自动）、论证深度（标准／压缩）。此项给出推荐默认（正文精确引注 · Markdown · 分段确认 · 标准深度），请用户确认或调整。
4. **法律检索后端（legal_db）**——决定法条校验铁律的核验级别。只读探测后**必须提交用户确认**：绑定探测到的专业后端为一级来源，或确认降级到二级（官方网页）／三级（内置知识）。详见 §4；未确认检索级别前不得进入 W1 选定法源。

**其余可选能力槽（文档解析、全网搜索、Word 输出、学术论文检索）非必答**：只读探测自动登记，探测不到按降级链处理，绝不要求用户登记工具产品后才开工。必答项仅限上述四项，不为冷启动追加全套能力登记轮次。

## 3. 适用地域（jurisdiction）

劳动法的最低工资、社平工资与三倍封顶线、失业金、医疗期与病假口径、一裁终局金额线及多数裁审口径均为**省级参数**，地域直接改变金额结论与口径选择。首次启动必须确定常用执业地／受诉地，判定顺序：

1. 已有上下文可推断（案情写明地点、用户此前说明执业地）→ 作为**预选默认**呈现，请用户确认；确认即采用，与用户后续确认的受诉地不一致时以案件受诉地为准；
2. 无法从上下文推断 → 直接提问：“常用适用地域（受诉地）是哪个省市？”；
3. 用户明确回答暂无固定地域、或本案为不指定地域的教学题 → 以全国性规范为主可继续分析，但地方参数类计算（N/2N 封顶、失业金、病假下限、一裁终局线）一律符号化表达并列“待人工核对清单”，**不得以任何默认地域硬编码数值**。此为**用户回答后**的处理，不得在用户未回答时自行套用。

地域确认结果供 `.user-config.md` 的 jurisdiction 字段使用；受诉地参数未沉淀的，按 `references/local-data-sources.md` 对应类别行锁定入口运行时检索，取值写入**案件工作目录**的地方参数缓存（非技能包内 `references/local-standards.md`），按地域、版本、时间和来源索引。

## 4. 法律检索后端（只读探测 → 首次确认，必答）

冷启动先用运行环境的 MCP／连接器列举能力**只读探测**是否存在可用的专业法条检索后端（元典、北大法宝等），跑一条最小真实用例确认可用性。探测结果**必须提交用户确认**（§2 必答项第 4 项），不得静默绑定、也不得静默降级：

- **探测到可用后端** → 呈现候选与最小用例结果，请用户确认是否绑定为一级来源；确认后登记能力槽契约，写入 `.user-config.md` 的 `legal_db.level = 一级`。
- **未探测到 / 用户不绑定** → 呈现降级方案（`references/research-protocol.md` §6 降级链：二级官方网页 / 三级内置知识），请用户确认接受的核验级别；确认后写入 `legal_db.level = 二级 / 三级`，即可开工，绝不因未配置而拒绝或通篇免责。

探测与确认与 §2 其余必答项在**同一轮交互**中一并完成，不单独增加“工具登记”轮次；用户确认（含确认降级）即满足本项。**未取得用户对检索级别的确认前，不得进入 W1 选定法源**——法条校验铁律的核验级别以本次确认为准，并在台账与正文如实标注。

能力槽契约（写入长期配置时用，字段适配劳动法的时际核验需求）：`level`（一级·已绑定后端 / 二级·官方网页 / 三级·内置知识）、`provider_name`（后端名称；降级时填 官方网页 / 内置知识）、`tools`（检索／取原文工具名；降级时留空）、`contract`（`article_locator`＝条号定位字段、`version_field`＝行为时版本/修正时点字段、`effectiveness_field`＝效力状态字段、`effective_value`＝现行有效取值、`title_format`／`number_format`＝规范名称与文号引用格式）。契约缺失某字段时，该项退回§6就地标注，不伪填。

## 5. 锚定表抽检（静默）

冷启动及每次会话启动时，按 [SKILL.md §八 法条锚定表](../SKILL.md) 抽检 5–8 条：A/B/C 组各抽 1–2 条（如“过错解除条款”“经济补偿计算条款”“加班费三倍率条款”“仲裁时效条款”），E 组（劳动争议司法解释二，法释〔2025〕12 号）**全量**。抽检经法律检索能力槽执行，未配置时按检索协议 §6 降级链二级核验。

抽检结果不打扰用户：命中即静默通过；命中失败在**案件工作目录 `verification-log.md`** 登记受影响条文，并在 W2a 候选清单中提示——报告引用前须补核验，未补核验的按降级链级别就地标注。技能包内的锚定表不在运行时修改。

## 6. 完成标志：写入 .user-config.md

**首次启动取得用户对 §2 必答项的回答后，立即写入 `.user-config.md`**——该文件的存在即“已完成首访”的标志，后续会话据此跳过访谈。写入内容限于长期偏好（jurisdiction、mode、citation、format、confirmation、depth）与法律检索能力槽契约、锚定表抽检结果；**案情、人员、工资、时效和地方数值不写入长期偏好**（这些进案件工作目录）。Word 转换不能取得时保持 Markdown，不伪称已生成。

```markdown
# gutachten-labor-case 用户配置

jurisdiction: <省／市，如 河南·郑州；未确定留空>
mode: academic | litigation | compliance
citation: 正文精确引注 | 脚注引注
format: markdown | docx
confirmation: 分段确认 | 全自动
depth: 标准 | 压缩

legal_db:
  level: <一级·已绑定后端 | 二级·官方网页 | 三级·内置知识>
  provider_name: <后端名称；降级时填 官方网页 / 内置知识>
  tools: <检索／取原文工具名；降级时留空>
  contract:
    article_locator: <条号定位字段>
    version_field: <行为时版本/修正时点字段>
    effectiveness_field: <效力状态字段>
    effective_value: <现行有效取值>
    title_format: <规范名称引用格式>
    number_format: <文号引用格式>

anchor_check:
  date: <YYYY-MM-DD>
  fail: [<命中失败的语义名称列表，无则空>]
```
